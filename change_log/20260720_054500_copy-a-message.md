# Copy a message

Implements [plans/20260720_053255_copy-and-paste-support.md](../plans/20260720_053255_copy-and-paste-support.md).

## What the user reported

1. No way to copy a message.
2. Long-press paste did not work in the Reply / Compose boxes.

During implementation the user clarified that **system-level copy and paste inside
the compose and reply windows is already handled**, so only the "copy a message"
half was built. Steps 4 and 5 of the plan (an app-drawn Paste button and a
long-press paste gesture on the composers) were **dropped**, and the one edit
already made to the reply composer was reverted.

## Changed

**`app/src/main/java/in/sreerajp/sms_sentry/ui/SmsOrganizerUi.kt`**

- Added `SelectionContainer` to the imports.
- `ThreadScreen`: added a `clipboardManager` handle next to the existing `context`.
- `ThreadScreen` selection toolbar: new **Copy** icon button, sitting between
  mark-unread and delete. Long-press a bubble to enter selection mode, tick the
  messages, tap Copy. It copies the bodies joined by a blank line, in on-screen
  (timestamp) order rather than tap order, toasts "Message copied" /
  "N messages copied", then clears the selection like the other actions.
  Test tag `thread_copy_selected`.
- `MessageDetailScreen`: wrapped the message body in a `SelectionContainer`, so
  part of a message (a link, a reference number) can be dragged out with the
  system selection toolbar. Without this the body was a plain `Text` and the
  system toolbar could not appear on it at all.
- `MessageDetailScreen`: new full-width **Copy message** button that copies the
  whole `msg.body` and toasts "Message copied". It sits below the existing Copy
  OTP button when there is an OTP, and stands alone when there isn't.
  Test tag `copy_message_button_<id>`.

**`app/src/test/java/in/sreerajp/sms_sentry/CopyMessageTest.kt`** (new)

- Robolectric + Compose test: renders `MessageDetailScreen`, clicks the copy
  button, asserts the system clipboard holds the exact message body.

## Verification

- `./gradlew :app:compileDebugKotlin` — clean.
- `./gradlew :app:testDebugUnitTest --tests "...CopyMessageTest"` — passes.
- Full suite: 42 tests, 4 failures. All 4 (`ExampleRobolectricTest`,
  `GreetingScreenshotTest`, `P2PSyncCryptoTest`, `SyncSettingsTest`) are
  **pre-existing** — confirmed by stashing these changes and re-running, which
  produces the same 4. They fail at `classMethod` with
  `UnsupportedOperationException` from Robolectric's `DefaultSdkProvider`,
  i.e. `@Config(sdk = [36])` is not supported by the pinned Robolectric. The new
  test therefore uses `sdk = [34]`, matching `ContactSuggestionsTest`.
