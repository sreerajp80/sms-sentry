# Change log: Kotlin P2P sync → full Flutter-guide parity

Implements [plans/20260709_103756_p2p-flutter-parity.md](../plans/20260709_103756_p2p-flutter-parity.md)
(approved). Reworks the P2P sync from immediate-send / host-overwrites into the Flutter guide's
**connect-then-choose** flow with **add-only, client-wins** merge, a **settings allow-list**, and
extra hostile-peer hardening. Breaking wire + KDF change — both phones must run this build.

## Documentation

- **`p2p-sync-implementation-guide.md`** (repo root) — updated the portable Kotlin guide to the new
  design first (per request): 300k KDF, connect-then-choose handshake, hold-open host +
  `sendToConnectedClient`, idle auto-stop / single client / drop detection, `decrypt` length guard,
  selective payload, add-only merge table, settings allow-list, versioned QR, new state model.

## Code

- **`engine/P2PSyncEngine.kt`** (rewrite):
  - `SyncState`: added `WaitingForSender`; `Hosting(ip, port, code, clientConnected, sending)`;
    `Completed(importedCount, exportedCount, addedCount, skippedCount)`.
  - New `SyncSelection` (per-category flags; `includesMessages` so finance/reminders carry
    messages; `full()`).
  - Constants: `PBKDF2_ITERATIONS = 300_000`, `PAYLOAD_VERSION = 3`, `HOST_IDLE_TIMEOUT_MS`,
    `PAYLOAD_WAIT_MS`, sync-mode literals. `decrypt` now guards a too-short ciphertext.
  - Host: binds a **random port** (`ServerSocket(0)`); idle auto-stop (120 s); single client;
    authenticates, ACKs, and **holds the connection open**; a drop-watcher notices a peer
    disconnect. `sendToConnectedClient(selection, syncMode, …)` builds the selective payload
    (+ `SyncSettings.collect`) and pushes it, then tears down (one payload per session). `teardown`
    closes sockets/jobs without clobbering the visible state; `stopHostServer` = teardown + Idle.
  - Client `connectAndSync(hostIp, port, pin, …)`: gained `port`; after ACCEPT enters
    `WaitingForSender` and reads the payload with the long timeout.
  - `buildSyncPayload(snapshot, selection, syncMode, settings)`: emits only selected keys + mode.
  - `importSyncPayload`: v==3 check, all caps kept, **add-only** with an added/skipped tally;
    finance/reminders imported only for a newly-added parent message; scheduled add-only on
    `(recipient, body, scheduledTime)`; settings applied via `SyncSettings` (overwrite on full).

- **`data/SmsRepository.kt`**: `importSyncedMessage` is now **add-only** (returns `ImportedMsg(id,
  added)`, no overwrite); `importSyncedRules` add-only (returns `MergeCounts`); new `ImportedMsg` /
  `MergeCounts` DTOs.

- **New `util/SyncSettings.kt`**: explicit allow-list (auto-mark-read secs, reminder alerts/lead/
  near/vibration) with `collect(context)` and `apply(context, json, overwrite)` (type-check + clamp;
  fill-only unless overwrite). Theme / SIM / muted / paid / drafts excluded.

- **`util/SyncQr.kt`**: QR now carries `v=1`; parser requires it (rejects foreign/older QRs).

- **`ui/SmsOrganizerViewModel.kt`**: `joinSyncServer(ip, port, pin)`; new `sendFullSync()` /
  `sendSelectiveSync(selection)`.

- **`ui/SmsOrganizerUi.kt`**: host status chip (waiting/connected); a **"Choose what to share"**
  section (Full Sync + per-category checkboxes via a new `SyncCheckRow`, with the "won't override"
  note); a `WaitingForSender` client state; `Completed` shows added/kept; manual join gained a
  **Port** field; QR scan fills ip + port + code.

- **`docs/architecture.md`**: rewrote the P2P section for the new flow, add-only merge, settings
  allow-list, random port, and versioned QR.

## Tests

- **`P2PSyncCryptoTest.kt`**: updated `buildSyncPayload` to the v:3 signature; added a
  selection test (unselected categories absent, messages ride along with finance) and a
  `decrypt` too-short-ciphertext rejection test. Existing crypto tests unchanged.
- **`SyncQrTest.kt`**: asserts the `v=1` marker and rejects missing/old-version QRs.
- **New `SyncSettingsTest.kt`**: fill-only vs. overwrite, clamping, and unknown-key rejection.

Verification: `:app:compileDebugKotlin` + `:app:compileDebugUnitTestKotlin` build; the
P2PSyncCrypto / SyncQr / SyncSettings unit tests pass. A real two-phone LAN transfer (the one path
loopback can't exercise) still needs a manual check before release.
