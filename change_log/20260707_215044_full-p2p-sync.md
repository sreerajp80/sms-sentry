# Change log: Full P2P sync (host → fresh phone)

Implements plan [plans/20260707_214102_full-p2p-sync.md](../plans/20260707_214102_full-p2p-sync.md).

## What changed

The P2P sync used to send only five message fields and re-classify on the client, losing
filter rules, manual reminders, reminder settings, and scheduled messages. It is now a
**one-way full clone** (host → a fresh phone) that copies the host's whole database and
**preserves the host's classification** instead of re-computing it, so the new phone mirrors
the host.

### New wire payload (`v: 2`)

The flat JSON message array was replaced with a versioned object carrying five tables:

- `messages` — `sender`, `body`, `timestamp`, `category`, `simId`, `isBlocked`, `isRead`,
  `type`, `isMms` (flag only), `status`.
- `rules` (`FilterRule`), `finance` (`FinanceTx`), `reminders` (`ReminderSms` incl.
  `recurrence` / `alertEnabled`), `scheduled` (`ScheduledSms`).
- `finance` / `reminders` link to their parent message by its **index** in `messages`
  (`msgIdx`) because row ids differ per phone.

This is a **breaking wire-protocol change** — both phones must run this build.

### Device-specific fields intentionally NOT synced

They cannot be replayed on another phone, so they stay `null` / default on the client:
`SMSMessage.systemId`, `threadId`, and `attachmentUri` / MMS media. The `isMms` flag and the
text body still cross.

### Import behaviour

The client inserts messages first (capturing local row ids), then re-links and inserts rules,
finance, reminders, and scheduled messages via dedicated repository helpers (all Room writes
stay inside `SmsRepository`). Imported scheduled messages get their alarm re-armed
(`ScheduledSmsScheduler`); reminder alarms re-arm through the ViewModel's existing reactive
`ReminderAlarmScheduler.reconcile`. On a re-run, an existing message (matched on
sender/body/timestamp) is overwritten with the host's values (idempotent). The untrusted
payload is validated: version check, per-array size caps, per-field length cap, positive
timestamps, finite numbers, and bounds-checked `msgIdx`.

## Files changed

- **`app/src/main/java/in/sreerajp/sms_sentry/data/SmsDao.kt`** — added
  `getAllTransactionsOnce()` and `updateMessageSyncFields(...)`.

  `insertSyncedFinance()`, `insertSyncedReminder()`.
- **`app/src/main/java/in/sreerajp/sms_sentry/engine/P2PSyncEngine.kt`** — `buildSyncPayload()`
  (host) and `importSyncPayload()` (client) for the `v:2` format with validation; host now
  serializes `collectSyncData()`; `connectAndSync(...)` gained an `appContext` parameter and
  re-arms scheduled alarms; added `PAYLOAD_VERSION` and the extra size caps.

  passes the application context into `connectAndSync`.
- **`docs/architecture.md`** — rewrote the P2P section to describe the full clone and the
  device-specific exclusions.
- **`app/src/test/java/in/sreerajp/sms_sentry/P2PSyncCryptoTest.kt`** — added a
  `buildSyncPayload` round-trip test asserting the `v:2` shape, `msgIdx` links, and that
  device-specific columns are not serialized.

## Notes / non-goals

- No DB schema change (no new columns/entities), so no `SmsDatabase` version bump or migration.
- Two-way merge is out of scope (kept one-way per the decision).
- MMS media blobs are not transferable over the current text/JSON socket; only the `isMms`
  flag and text body cross.
