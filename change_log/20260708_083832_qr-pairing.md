# Change log: QR-code pairing for P2P sync

Implements plan [plans/20260707_215651_qr-pairing.md](../plans/20260707_215651_qr-pairing.md).

## What changed

The host now shows a **QR code** for pairing, and the client can **scan it** to auto-fill the
IP + pairing code and connect — no more typing the IP and 64-char code by hand. Manual entry
still works as a fallback.

Security is unchanged: the QR is read visually off the host's screen, so the pairing code is
still transferred out-of-band and never crosses the socket.

### Host

In the active "Hosting" card, below the IP / port / code, the app renders a QR encoding
`smssentry://sync?ip=<ip>&port=<port>&code=<rawCode>`. The bitmap is encoded once per session
(`remember` keyed on ip/port/code).

### Client

The Join panel gained a **"Scan QR code"** button. It launches `zxing-android-embedded`'s
`ScanContract` scanner (which handles the camera preview and the runtime CAMERA permission
prompt). On a valid Sentry QR the fields are filled and `joinSyncServer` is called immediately;
a foreign/malformed QR shows a "Not a Sentry sync code" toast and does nothing.

## Files changed

- **`gradle/libs.versions.toml`** — added `zxingEmbedded = "4.3.0"` and the
  `zxing-android-embedded` library entry.
- **`app/build.gradle.kts`** — added `implementation(libs.zxing.android.embedded)`.
- **`app/src/main/AndroidManifest.xml`** — added the `CAMERA` permission and an optional
  `android.hardware.camera` `uses-feature` (camera not required, so camera-less devices still
  install and pair by typing).
- **New `app/src/main/java/in/sreerajp/sms_sentry/util/SyncQr.kt`** — `buildSyncQrContent` /
  `parseSyncQrContent` (pure JVM, unit-testable) and `encodeQrBitmap` (ZXing/Android).
- **`app/src/main/java/in/sreerajp/sms_sentry/ui/SmsOrganizerUi.kt`** — host QR `Image` in the
  Hosting card; client "Scan QR code" button + `ScanContract` launcher in the Join panel;
  added imports (`asImageBitmap`, `ScanContract`, `ScanOptions`, `SyncQr`).
- **`docs/architecture.md`** — noted QR pairing in the P2P section (out-of-band, security
  unchanged, camera optional).
- **New `app/src/test/java/in/sreerajp/sms_sentry/SyncQrTest.kt`** — round-trip + rejection
  tests for the QR content codec.

## Verification

- `./gradlew :app:compileDebugKotlin` — success (exit 0).
- `./gradlew :app:testDebugUnitTest --tests "in.sreerajp.sms_sentry.SyncQrTest"` and
  `:app:processDebugMainManifest` — BUILD SUCCESSFUL (codec tests pass; the new dependency
  resolves and the manifest merges cleanly).

## Notes / non-goals

- No change to the sync wire protocol or crypto — this only changes how the IP + code get into
  the client's join form.
- `zxing-android-embedded` uses its own full-screen scanner activity (legacy camera), not an
  in-app Compose CameraX scanner. Works on API 24–36; a modern in-app scanner would be a larger
  change.
- QR bitmap rendering was not unit-tested (needs Android); the string codec is covered.
