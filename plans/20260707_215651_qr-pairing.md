# Plan: QR-code pairing for P2P sync

**Status:** completed

## Goal / context

Today, to sync, the client user must read the host's **IP address** and the **64-char pairing
code** and type them into the join form. The user wants the host to show a **QR code** that the
client can **scan** to fill those in (and connect) automatically.

Security is unchanged: the pairing code is still transferred **out-of-band** (scanned visually
from the host's screen, never sent over the socket). Anyone who can scan the QR is someone who
can already read the on-screen code — same threat model. So this is a pure UX improvement.

## Approach / key decisions

- **One dependency: `com.journeyapps:zxing-android-embedded`.** It provides both:
  - QR **generation** (`BarcodeEncoder`) for the host, and
  - QR **scanning** via a ready-made `ScanContract` activity-result launcher for the client
    (it handles the camera preview and the runtime CAMERA permission prompt itself).

  This avoids hand-writing a CameraX preview + a ZXing frame analyzer. Trade-off: the scanner
  opens as its own full-screen activity (not an in-app Compose camera). Acceptable for a
  utility screen. (The commented-out CameraX deps in the catalog stay unused.)
- **QR payload format** (compact, self-identifying so a random QR is rejected):
  `smssentry://sync?ip=<ip>&port=<port>&code=<rawCode>` — `code` is the raw 64-char code (no
  hyphens); the client runs it through `normalizeCode` on connect anyway.
- **After a successful scan**, the client auto-fills the IP + code fields **and immediately
  connects** (calls `joinSyncServer`). A malformed / non-Sentry QR shows a Toast and does
  nothing.
- The QR is shown in the **active "Hosting" card** (where the IP/port/code already appear), so
  the IP shown in the QR is the final listening address.

## Files to change

1. **`gradle/libs.versions.toml`**
   - Add version `zxingEmbedded = "4.3.0"` and library
     `zxing-android-embedded = { group = "com.journeyapps", name = "zxing-android-embedded", version.ref = "zxingEmbedded" }`.

2. **`app/build.gradle.kts`**
   - Add `implementation(libs.zxing.android.embedded)`.

3. **`app/src/main/AndroidManifest.xml`**
   - Add `<uses-permission android:name="android.permission.CAMERA" />` and
     `<uses-feature android:name="android.hardware.camera" android:required="false" />`
     (camera is optional so the app still installs on camera-less devices — the host side and
     manual typing still work).

4. **New: `app/src/main/java/in/sreerajp/sms_sentry/util/SyncQr.kt`**
   - `data class SyncQrData(val ip: String, val port: Int, val code: String)`.
   - `buildSyncQrContent(ip: String, port: Int, code: String): String` — builds the
     `smssentry://sync?...` string (URL-encoding values). **Pure Kotlin** (no Android APIs) so
     it is unit-testable.
   - `parseSyncQrContent(text: String): SyncQrData?` — parses/validates the string, returns
     `null` if it is not a Sentry sync QR. **Pure Kotlin.**
   - `encodeQrBitmap(content: String, sizePx: Int): Bitmap` — uses `BarcodeEncoder` /
     `QRCodeWriter` (Android/ZXing) to render the QR. Kept separate from build/parse so the
     string logic stays testable without Android.

5. **`app/src/main/java/in/sreerajp/sms_sentry/ui/SmsOrganizerUi.kt`**
   - **Host (`SyncState.Hosting` card):** render `encodeQrBitmap(buildSyncQrContent(state.ipAddress, state.port, state.code), …)`
     as an `Image`, with a small caption like "Scan this on the other phone." Remember the
     bitmap keyed on the content so it is not re-encoded every recomposition.
   - **Client (Join panel):** add a "Scan QR code" `OutlinedButton` above the IP field. It uses
     `rememberLauncherForActivityResult(ScanContract())`; on a non-null result, call
     `parseSyncQrContent(...)` → on success set `ipInput` + `pinValue` and call
     `viewModel.joinSyncServer(ipInput, pinValue)` (then close the panel); on failure show a
     Toast ("Not a Sentry sync code"). Manual typing stays as a fallback.

6. **`docs/architecture.md`**
   - One sentence in the P2P section: pairing can be done by scanning a QR the host shows; the
     QR carries IP/port/code and is still out-of-band (the code never crosses the socket), so
     the security model is unchanged.

7. **`app/src/test/java/in/sreerajp/sms_sentry/SyncQrTest.kt`** (new)
   - Pure-Kotlin round-trip + rejection tests for `buildSyncQrContent` / `parseSyncQrContent`
     (valid round-trip; a plain URL / random text returns `null`; the code survives verbatim).

## Notes / non-goals

- No change to the sync wire protocol or crypto — this only changes how IP + code get **into**
  the client's join form.
- `zxing-android-embedded` uses the legacy camera activity; it works on API 24–36 but is not a
  modern in-app Compose scanner. If a fully in-app CameraX + ML Kit scanner is preferred, that
  is a larger change — say so and I will re-plan.
- Camera is declared **not required**, so devices without a camera still install and can pair
  by typing.
