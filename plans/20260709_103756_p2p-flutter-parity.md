# Plan: Bring Kotlin P2P sync to full Flutter-guide parity

**Status:** completed

## Goal / context

Rework the Kotlin P2P sync so it matches the Flutter guide's design:

- **Connect-then-choose flow.** The host binds a socket, a client connects and is
  acknowledged immediately (both sides show "connected"), and only then does the **sender
  choose what to share** (Full sync or selected categories). The host **holds the connection
  open** after authentication and pushes the chosen payload on that action.
- **Add-only, client-wins merge.** The receiver keeps its own data. Any record it already has
  is skipped (matched on a stable natural key); the receiver is never overridden. This
  reverses the current "host overwrites" clone behavior (a product change you approved).
- **Settings allow-list.** A small, explicit set of non-sensitive behavior settings can be
  synced (fill-only on a selective sync, overwrite on a full sync).
- **Hostile-peer hardening from the guide:** host idle auto-stop, single client at a time,
  drop detection while held open, one payload per session, a defensive `decrypt` length
  guard, and a stronger KDF.

Both phones must run this build (the wire protocol and KDF change — same-build requirement was
already documented). This supersedes the immediate-send, host-overwrites design in
`plans/20260707_214102_full-p2p-sync.md`.

## What changes vs. today

| Area | Today (v:2) | After (v:3) |
| --- | --- | --- |
| Flow | Host pushes whole DB immediately on auth | Host acks, holds open, sender picks what to push |
| Merge | Host overwrites / re-links | Add-only, client-wins (skip existing) |
| Selection | Everything | Full **or** per-category checkboxes + settings |
| Port | Fixed 8243 | Random OS-assigned (`ServerSocket(0)`); manual join gains a port field |
| KDF | PBKDF2 120k | PBKDF2 300k |
| Idle/host | Accept loop runs forever | 120s idle auto-stop; stop after one payload |
| Drop | Not detected | Detected while held open → back to "waiting" |
| `decrypt` | No min-length check | Rejects ciphertext shorter than the IV |
| Settings | Not synced | Explicit non-sensitive allow-list |
| QR | `smssentry://sync?ip&port&code` | adds `&v=1`; parser requires it |

## Wire protocol (v:3, breaking)

Handshake byte order is unchanged; the difference is the host **waits** before sending the
payload, and the payload shape/version change:

```
Host → Client   base64(salt)              (clear; salt is not secret)
Client → Host   encrypt(HELLO_SYNC)
Host → Client   encrypt(ACCEPT_SYNC)      immediately on successful auth
      …host holds open; sender picks data…
Host → Client   encrypt(payloadJson)      pushed on the sender's action
```

Payload (a category key is present **only when selected**, so the receiver can tell
"0 sent" from "not included"):

```json
{
  "v": 3,
  "syncMode": "full" | "incremental",
  "messages":  [ … ],
  "rules":     [ … ],
  "finance":   [ … ],
  "reminders": [ … ],
  "scheduled": [ … ],
  "settings":  { "reminder_lead_days": 2, … }
}
```

- The client sets `WaitingForSender` after `ACCEPT_SYNC` and reads the payload with a **long
  timeout** (`PAYLOAD_WAIT_MS`, 10 min), distinct from the 30s per-line `SOCKET_TIMEOUT_MS`.
- `finance[].msgIdx` / `reminders[].msgIdx` still index into `messages[]`. Finance/reminder
  rows are only imported for a message that was **newly added**; if a message already existed
  on the receiver, its derived rows are assumed already present and are skipped (keeps add-only
  clean). Selecting Finance/Reminders therefore implies Messages (enforced in the UI + when
  building the payload).

## Add-only merge rules (natural keys)

| Category | Natural key | On match |
| --- | --- | --- |
| messages | `(sender, body, timestamp)` (existing `findMessageId`) | skip; do not overwrite |
| rules | `(type, value)` | skip; keep receiver's `targetCategory` |
| scheduled | `(recipient, body, scheduledTime)` | skip |
| finance/reminders | parent message added? | insert only if parent was newly added |

Counts (`added` / `skipped`) are returned and shown in the completion summary.

## Settings allow-list (non-sensitive, portable)

Stored in the `theme_prefs` SharedPreferences. Synced set (behavior only; read at use-time so
they take effect without a restart):

- `auto_mark_read_secs` (Int, clamp 0..3600)
- `ReminderAlarmScheduler.PREF_ALERTS_ENABLED` (Boolean)
- `ReminderAlarmScheduler.PREF_LEAD_DAYS` (Int, clamp 0..30)
- `reminder_near_days` (Int, clamp 0..30)
- `SmsNotificationHelper.PREF_REMINDER_VIBRATION` (Boolean)

**Excluded by design:** theme prefs (`selected_theme` / `is_dark_theme` / `is_system_theme` —
would need a restart to reflect, avoided to prevent a half-applied look), `default_sms_sim`
(SIM slots differ per phone), `muted_senders` / `paid_message_ids` (device/message-specific),
drafts/compose draft. Fill-only unless the sync is a Full sync (`overwrite`).

## Files to change

1. **`app/src/main/java/in/sreerajp/sms_sentry/engine/P2PSyncEngine.kt`** (largest change)
   - `SyncState`: add `WaitingForSender`; give `Hosting(ip, port, code, clientConnected,
     sending)`; extend `Completed` with `addedCount` / `skippedCount`.
   - Constants: `PBKDF2_ITERATIONS = 300_000`, `PAYLOAD_VERSION = 3`, `HOST_IDLE_TIMEOUT_MS =
     120_000`, `PAYLOAD_WAIT_MS = 600_000`. Wire literals unchanged.
   - `decrypt`: reject `all.size <= IV_LEN` with a thrown `SyncException`/IOException (guard
     before `copyOfRange`).
   - Host: bind `ServerSocket(0)` (random port); idle `Timer`/coroutine stops the server if no
     client authenticates within `HOST_IDLE_TIMEOUT_MS`; single active client (`_activeSocket`
     /`_activeKey`/`_activeWriter`, extra connections closed); on auth send `ACCEPT_SYNC`,
     cancel idle timer, set `Hosting(clientConnected=true)`, and launch a watcher that blocks
     on `reader.read()` to detect a peer drop (→ `clientConnected=false`, keep hosting).
   - `sendToConnectedClient(selection, syncMode)`: build the selective payload from
     `repository.collectSyncData()` + `SyncSettings.collect(...)`, encrypt, write, then
     `stopHostServer()` (one payload per session); `Completed` with exported count.
   - Client `connectAndSync(hostIp, port, pin, repository, appContext)`: add `port`; after
     `ACCEPT_SYNC` set `WaitingForSender`, raise `soTimeout` to `PAYLOAD_WAIT_MS` for the
     payload read, decrypt, then hand to `importSyncPayload`.
   - `buildSyncPayload(snapshot, selection, syncMode, settings)`: emit only selected keys +
     `syncMode` + `settings`.
   - `importSyncPayload`: version == 3 check; keep all size/field caps; drive **add-only**
     inserts, tracking per-index `added` flag + local id; gate finance/reminders on the parent
     being added; apply settings via `SyncSettings.apply(appContext, map, overwrite = syncMode
     == "full")`; return `(added, skipped)`.
   - Concurrency: `@Volatile` fields + a `Mutex`/`stopped` flag guarding send-vs-drop teardown
     (mirrors the guide's guards). Thread-safety around `_activeSocket`.

2. **`app/src/main/java/in/sreerajp/sms_sentry/data/SmsRepository.kt`**
   - `importSyncedMessage` → **add-only**: if `findMessageId` hits, return
     `ImportedMsg(existingId, added=false)` **without** overwriting/clearing derived rows; else
     insert and return `added=true`.
   - `importSyncedRules` → add-only: skip `(type, value)` that already exists (no category
     overwrite); return added/skipped.
   - New `importSyncedScheduled(...)` or an in-engine dedup using `getAllScheduledOnce()` on
     `(recipient, body, scheduledTime)`.
   - Add small result DTOs (`ImportedMsg`, `MergeCounts`) as needed. No DAO changes (all
     required queries — `findMessageId`, `getAll*Once`, inserts — already exist).

3. **New: `app/src/main/java/in/sreerajp/sms_sentry/util/SyncSettings.kt`**
   - `ALLOWED` allow-list (keys + type + validator/clamp).
   - `collect(context): Map<String, Any>` — read the allow-listed prefs for the host payload.
   - `apply(context, map, overwrite): Int` — validate each entry, write to `theme_prefs`
     fill-only unless `overwrite`; ignore unknown keys. Pure-ish (Android `Context` only) and
     unit-testable under Robolectric.

4. **`app/src/main/java/in/sreerajp/sms_sentry/util/SyncQr.kt`**
   - Add `&v=1` to `buildSyncQrContent`; `parseSyncQrContent` requires `v == "1"` (reject
     otherwise) so a foreign/older QR is rejected. Port already carried.

5. **`app/src/main/java/in/sreerajp/sms_sentry/ui/SmsOrganizerViewModel.kt`**

## Notes / non-goals

- **Breaking:** v:3 is not wire- or key-compatible with v:2 (KDF iterations + hold-open timing
  + payload version). Both phones need this build.
- **No DB schema change**, **no new dependencies**, **no manifest change** (INTERNET /
  ACCESS_WIFI_STATE / CHANGE_WIFI_STATE / CAMERA already present).
- Two-way sync stays **out of scope** (host pushes; client imports).
- MMS media still not transferred (text/JSON channel) — unchanged.
- Loopback covers everything except a real two-phone LAN transfer, which must be verified
  manually before release.
